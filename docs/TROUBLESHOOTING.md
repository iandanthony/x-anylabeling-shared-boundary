# 常见问题与排查

## 软件打开了，但没有新增菜单

检查是否运行本仓库 `launch.py`，或指向本仓库 `.pyw` 的快捷方式。直接运行上游 `xanylabeling` / 原 exe 不会加载扩展。确认 `x-anylabeling-cvhub` 为 4.0.6、Shapely 为 2.1.2；保存标注后重启以加载更新。

## Shapes 已勾选，但按钮仍要求选择多边形

勾选框用于显示 / 隐藏。按 Ctrl+J，单击名称行；多个同类形状时看画布高亮确认具体对象。确保是已经完成的多边形且没有锁定。不要靠悬停，也不要右键点列表行。

## 连续描边缩放后边缘跑偏

更新到 1.0.3，保存已完成标注并重启桌面共边版。连续描边时把鼠标停在边界位置，**Ctrl+滚轮** 缩放；Ctrl 按住期间不自动加点，松开后实际移动鼠标才继续描边。已有顶点坐标保持不变。

不按 Ctrl 的滚轮是滚动画面，Shift+B 编辑画笔的滚轮是改变画笔半径。缩放后出现留白是为保持图像边缘处的锚点；Ctrl+F 可适合窗口，Ctrl+Shift+F 可适合宽度。旧版已经加错的顶点需撤销或手工修正。

## 绘制时误双击，关闭类别窗口后无法继续

保存已完成标注，更新到 1.0.2 并重启。绘制普通多边形或 Ctrl+N 连续描边时，关闭类别窗口的 × / Cancel / Esc 会保留已有顶点并恢复原绘制状态。普通模式继续单击，连续描边继续移动鼠标；无需重新点创建工具。完成后 Enter → 确认类别 → Ctrl+S 保存。

草稿尚未提交，关闭弹窗时不会自动扣除重叠；只有确认类别后才执行裁剪。如果要放弃整个草稿，关闭弹窗后在画布再按 Esc。之前已经丢失且没有保存的顶点无法通过本次更新自动重建。

## 肉眼重叠，但提示没发现重叠

1. 确认两形状均在当前图片、已经完成，不是 SAM 临时预览。
2. 确认目标和参考都是真正的多边形。
3. 不同类使用其他类别扣除按钮，同类使用同类扣除按钮。
4. 同类若 Group ID 相同且非空会跳过；它们被视为同一对象分块。
5. 仅共用一条边没有面积重叠，提示无重叠是正常的。
6. 当前扩展会解析自交多边形的可用面积，但极度退化或没有面积的轮廓仍不可用；必要时手工修正。

## 扣除方向反了

Shapes 扣除按钮中选中的图形是要缩小的一方。要保留工程渣土边界，就选装修垃圾，再执行扣除，以工程渣土作为参考。

1.0.1 默认“旧区域优先：自动裁剪新多边形（共边）”，旧区域保留，新区域被扣除。若仍看到“新区域覆盖旧多边形”，保存并关闭软件，确认更新了快捷方式实际指向的扩展目录，再重新启动。已被旧版裁掉的部分需通过撤销或备份恢复；更新不会自动重建。

“以画布选中图形为准裁剪其他类别”是反方向的手动工具；“共边精修”开启后会联动邻区。正常保留旧边界时使用默认自动裁剪。误操作 Ctrl+Z 撤销。

## 新多边形完成后消失

如果新多边形完全位于其他类别旧区域内，按旧区域优先规则扣除后没有剩余面积，软件会移除它，并在底部显示“完全被覆盖”提示。Ctrl+Z 撤销；需要保留重叠时，先关闭自动裁剪再重画。

## 缩小后另一侧没有补回来

单次扣除不会持续联动。选中目标并开启“共边精修：联动相邻类别”后再修公共边；拖点需松开，画笔需右键提交。撤销和切换图片会结束联动，继续修时重新开启。联动不能自动补此前已经存在的所有空白缝隙。

## 普通多边形不能框选顶点

需要启动新增“多边形圈选顶点拉直”，再逐点画临时选区。仅选中图形属于普通编辑状态，不会自动开启顶点选区。选区闭合先预览，Enter 才执行；连续顶点至少三个。

## 连续描边太稀或太抖

Ctrl+N 使用画笔多边形，编辑 → 画笔多边形点间距… → Brush Point Distance 改为 5 → Save。普通 P 多边形仍需逐点点击。距离按屏幕像素计算；放大后更细，太小则记录手抖。已有形状不会按新参数重新采样。

## SAM2 Large 仍然不贴边

Large 并不保证类别交界精准。加载模型后执行细节优先预设，+Rect 收紧到目标和少量背景，逐个添加明确的正负点，观察后再 F 完成。轮廓精细度只影响简化，不能纠正前景分类错误；复杂交界仍需人工修边。

## 模型下载失败

确认网络与代理可访问模型来源；通过上游模型配置检查下载地址及本地路径。初次启动有 GUI 不代表模型已下载。迁移配置后旧电脑绝对路径可能失效。支持的本地模型加载方式见[上游自定义模型说明](https://xanylabeling.com/docs/x-anylabeling/custom_model)。

## CUDA / DLL 错误或推理很慢

1. 确认使用 GPU 要求安装且运行的是同一个 Python 环境，检查 `python -m pip show onnxruntime-gpu`。
2. 同一环境避免同时安装 `onnxruntime` 和 `onnxruntime-gpu`；推荐重新建立干净 GPU 环境，不在正在使用的环境反复覆盖。
3. `nvidia-smi` 检查驱动，Windows 检查 Visual C++ x64 运行库。
4. 用终端 `python launch.py` 查看 DLL / CUDA 初始化日志；provider 列表并不保证实际推理成功。
5. 若 Large 超出机器资源，可用 Small / Base；手工标注及共边几何工具不依赖 SAM 权重。

## 桌面快捷方式闪退

用终端运行相同环境的 `python launch.py` 获取错误。检查快捷方式目标 Python、仓库路径、基础版本。不要只双击 `.pyw` 并假定 Windows 文件关联用了正确环境。

## 保存后找不到 JSON

先 Ctrl+S，再查看图片所在目录或指定输出目录；默认设置目录只保存配置，不等于标注输出目录。检查写入权限、是否确实完成类别确认。不要在标注过程中移动 / 重命名图片。

## 扣除后出现多个 Shapes 行

扣除可能产生断开的区域或孔洞。扩展将可用剩余面积拆成可保存的多边形，因此 Shapes 行数增加是预期行为。类别保留，实例导出前仍需复核 Group ID 和项目对象定义；不要简单凭行数统计堆体数。

## 更新后无法启动

本扩展适配基础软件 4.0.6。确认没有自行升级基础软件；记录错误信息、Python / PyQt / Shapely 版本及触发步骤。先使用测试图片复现，再检查 `python -m unittest test_shared_boundary.py test_launch.py` 和 `python smoke_ui.py`。
